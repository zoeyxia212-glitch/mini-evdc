# Roadmap to an enterprise edition

Compared with mature open-source platforms in the same space, these are the gaps, grouped into
phases. Each item lists the project it is modelled on and a test that proves it is done.

| Reference project | Relevant capabilities |
|---|---|
| [Apache CloudStack](https://github.com/apache/cloudstack) | domains with delegated admins, dynamic roles, OAuth2 / SAML / LDAP login, usage engine for billing, alerts |
| [ManageIQ](https://github.com/ManageIQ/manageiq) | self-service catalog with approval workflow, quota enforcement, chargeback, schema migrations |
| [Mist CE](https://github.com/mistio/mist-ce) | RBAC on every resource, cost quotas, machine leases, rules that call webhooks |
| [OpenStack Keystone](https://github.com/openstack/keystone) | domains / projects, role assignments, application credentials with expiry and access rules |

## Phase 1 – Platform foundation (ADR 0003)

| Item | Done when |
|---|---|
| FastAPI app replacing `http.server`; pydantic request / response models | all existing API tests pass against the new app; OpenAPI generated by FastAPI |
| `/api/v1` prefix; RFC 9457 problem+json errors; cursor pagination everywhere | contract tests for error shape and paging |
| SQLAlchemy 2 + Alembic; PostgreSQL in production, SQLite for tests | `alembic upgrade head` on an empty DB; CI job with a PostgreSQL service container |
| Worker process for sync and cloud actions; jobs table with status polling (`202` + `Location: /jobs/{id}`) | killing the API mid-sync does not lose the job |
| Idempotency keys on POST; per-key rate limits | repeating a POST with the same key returns the first result |
| OpenTelemetry traces across API → worker → cloud call | one trace per request visible in Jaeger in docker compose |
| Horizontal scaling: 2+ API replicas, RollingUpdate, PodDisruptionBudget, HPA | rollout without failed requests in a load test |

## Phase 2 – Identity (CloudStack, Keystone)

| Item | Done when |
|---|---|
| OIDC single sign-on (Entra ID / Okta / Keycloak) for the dashboard and API | login via Keycloak in docker compose |
| Custom roles built from permissions (`vm:create`, `policy:apply` …) | a "network operator" role that can edit rules but not VMs |
| Domains (groups of orgs) with delegated admins | a domain admin manages only their orgs |
| API keys with expiry, scopes and rotation; last-used tracking | expired or out-of-scope keys get 401 / 403 |

## Phase 3 – Governance and FinOps (ManageIQ, Mist, CloudStack usage engine)

| Item | Done when |
|---|---|
| Self-service catalog + approval workflow (auto-approve under a cost threshold) | request → approve → provision, all audited |
| Leases: VMs expire and are stopped / deleted after N days unless renewed | expired test VM stopped by the scheduler |
| Usage metering per org (hourly samples) and monthly showback / chargeback reports | invoice-style report per org matches the samples |
| Cost quotas per org and alerts at 80 % / 100 % | creation refused over quota |
| Webhooks / notifications for policy matches, sync failures, approvals (HMAC-signed) | receiver verifies the signature |
| Real price lists (AWS Price List API, Aliyun BSS, Azure Retail Prices) | prices refreshed daily, cached |

## Phase 4 – Operations and compliance

| Item | Done when |
|---|---|
| Helm chart alongside Kustomize; External Secrets for cloud credentials | `helm install` on kind in CI |
| Backups and restore drill for PostgreSQL | documented RPO / RTO, restore tested |
| SLOs (availability, sync freshness) with burn-rate alerts | alerts fire in a chaos test |
| Signed images (cosign) and verified at deploy time | unsigned image rejected by the cluster policy |
| Audit log export to SIEM (syslog / OTLP logs) | audit events visible in the log backend |

## Already in place

Adapters with retries and re-auth, unified inventory, change history, governance policies,
cost estimates, RBAC with org scoping, audit trail, OpenAPI, Prometheus metrics and alerts,
Grafana dashboard, health / readiness probes, graceful shutdown, hardened container and
Kubernetes manifests, CI with lint, tests on four Python versions, CodeQL, bandit, pip-audit,
Trivy and a release workflow with SBOM and provenance.
